# HTML-to-NativeWind fidelity

Objective: Bring every implemented UI screen closer to its matching `docs/ui/*.html` by comparing the rendered web route and reference at the same mobile viewport with Playwright, then making targeted React Native/NativeWind corrections.

Problem: The first pass reconstructed reference sections rather than translating their actual composition, dimensions, type hierarchy and Tailwind visual treatment. Static structural checks did not reveal rendered mismatches.

Scope: UI only, mock data and reference-represented visual behavior. Preserve existing navigation, cross-module storefront header, module ownership, and all uncommitted work. No backend or speculative redesign. Inspect actual HTML, route and Playwright evidence before each correction. NativeWind cannot literally reuse the HTML DOM; translate its structure and design tokens. Use the cached Playwright runtime without writing project dependencies/config, screenshots outside repo. Do not modify HTML references. No commits/push/PR requested.

Verification: For each screen compare reference and route in Chromium at the same viewport; correct meaningful visible differences and re-compare once. Note differences due to font/network/platform transparently. Avoid unrelated test suites; no claim of pixel identity without evidence. TDD off from prior UI work; Playwright here is visual verification, not a test-suite request. Route: read-only delegated browser mapping and bounded writer per small group of screens, one writer at a time. About 400 authored lines per unit is advisory. Delivery ask-on-risk.
